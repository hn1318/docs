NetTool is a graphical client for **FRP (fast reverse proxy)**. It does not tunnel anything itself — it handles the parts around it:

- downloading and managing the official `frpc` core
- keeping multiple configurations (server, token, a set of tunnels) in a form-based UI
- rendering a standard `frpc.toml` and starting / stopping the process
- **real** per-tunnel upload and download rates plus cumulative traffic (measured, not simulated)
- talking to five FRP providers' public APIs, so a remote tunnel can be imported and started in one click

Typical uses: exposing a local web service / SSH / RDP / NAS to the internet for a while, debugging WeChat callbacks, hosting a game for friends, and managing tunnels across several providers.

<Callout type="warn" title="NetTool is not a server">
You still need an frps endpoint — either your own, or an account with one of the [third-party providers](/docs/nettool/providers/).
</Callout>

Stack: Tauri 2 + Vue 3 + Rust. Primarily Windows (installer and portable builds; macOS and Linux can be compiled from source).

## Build from source

```bash
pnpm install
pnpm tauri dev        # development (Vite + Tauri)
pnpm tauri build      # package an installer
pnpm dev              # frontend only (Tauri APIs unavailable, styling work)
cd src-tauri && cargo test --lib   # backend unit tests
```

Main modules:

- Frontend: `src/` (Vue 3 + TS), pages in `src/views/`, shared components in `src/components/`
- `runner.rs` — orchestrates the frpc process, metering gateway and sampling
- `traffic.rs` — the local metering gateway
- `config.rs` — config rendering and parsing (TOML / legacy INI)
- `providers/` — per-provider adapters (`mod.rs` is the shared engine)
- `settings.rs` — app settings, storage directory, launch at login

Adding a provider: drop a submodule under `providers/` implementing `login_key / user / tunnels / profile`, then register it in `provider_metas()`.
